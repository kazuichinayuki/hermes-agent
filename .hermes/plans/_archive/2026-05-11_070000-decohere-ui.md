# Decohere 可查看和編輯界面方案

## 用戶旅程

### 入口

```
$ hermes decohere

  decohere — manage your session knowledge

  Sessions    Knowledge    Health

  View and manage the structured knowledge extracted from
  your conversations.
```

三個頂層分頁：
1. **Sessions** — 瀏覽和管理單個 session 的 ledger entries
2. **Knowledge** — 跨 session 共享知識庫的勾選/導入/編輯
3. **Health** — 數據質量檢查和修復

---

## Sessions 面板

### 數據流

```
hermes decohere sessions  ──→  選擇一個 session
                                    │
                         ┌──────────┴──────────┐
                         │                      │
                    list (瀏覽)             show (詳情)
                         │                      │
                    search (搜索)           edit (編輯)
                         │                      │
                    export (匯出)          delete (刪除)
```

### 交互模式：兩個層級

**L1: CLI 列表模式**（現有，優化輸出格式）

```
$ hermes decohere list --session abc123

  ▸ Turn 5  refactor        patch, terminal    2026-05-10 19:52
    Turn 4  code review     read_file, search  2026-05-10 19:38
    Turn 3  research        web_search, extract 2026-05-10 19:30
    Turn 2  config fix      patch              2026-05-10 19:15
    Turn 1  vision debug    vision_analyze     2026-05-10 19:00

  ↑↓ navigate  Enter view  / search  e edit  d delete  q back
```

**L2: 詳情/編輯模式**（新增）

```
── Turn 3 ── research ────────────────────────────────
  Tools:   web_search, web_extract
  Files:   (none)

  ── Concepts ──
  ▸ Codex /goal: OpenAI Codex CLI autonomous task loop
    [edit] [add to shared knowledge]

  ── Narrative ──
  ▸ Researched Codex CLI v0.128.0 /goal feature.
    Confirmed persistence across terminal restart.
    [edit]

  ── User Intent ──
  ▸ Research Codex /goal to see if it can automate
    decohere scheme building
    [edit]

  ── Critical Reflection ──
  ▸ improvements: Test /goal on large task token
    consumption
    [edit]

  [e] edit field  [a] add concept  [k] share knowledge  [d] delete  [q] back
```

編輯操作即時寫入 DB，不需要保存按鈕。`[undo]` 可以回滾上一次編輯。

### 搜索模式的交互

```
$ hermes decohere search "context window" --interactive

  ▸ Turn 3  concept   Codex /goal: ...               → view
    Turn 1  concept   context window: The maximum...  → view
    Turn 7  narrative "compression model context..."  → view

  Enter/view  ↑↓ navigate  q back
```

## 實現計劃

### 實現策略：三層，逐步疊加

**Layer 1: CLI 美化**（1-2 小時）
- 現有命令的輸出格式優化（表格對齊、顏色、截斷）
- 不改接口，只改 `print()` 格式

**Layer 2: 交互模式**（3-4 小時）
- 新增 `--interactive` flag 到 `list`, `show`, `search`, `knowledge`
- 基於 `prompt_toolkit`（已在 Hermes CLI 中使用）
- 以 `hermes_cli/commands.py` 的 `slash-command` 模式為參考

**Layer 3: TUI 面板**（5-6 小時，可選）
- 在 `ui-tui/src/` 下新增 `DecoherePanel.tsx`
- 只讀視圖優先（sessions list + show），編輯操作後續增量

### Layer 2 的文件變更


`interactive.py` 核心 API：

```python
def interactive_list(conn, session_id, limit=20) -> None:
    """prompt_toolkit 交互式列表。按鍵：↑↓導航, /搜索, Enter查看, e編輯, d刪除, q退出"""

def interactive_show(conn, turn_n) -> None:
    """詳情+編輯模式。按鍵：e編輯字段, a添加概念, d刪除, q退出"""

def interactive_knowledge_sources(hermes_home) -> None:
    """勾選式知識來源選擇器。space切換, Enter確認"""

def interactive_edit_field(conn, turn_n, field_path) -> None:
    """內聯字段編輯。Enter確認, Esc取消"""
```

### 依賴

```
Layer 1 (美化)  → 獨立，可直接做
Layer 2 (交互)  → 依賴方案 C 的 knowledge_cmd + shared_store
Layer 3 (TUI)   → 依賴 Layer 2 + 現有 TUI 框架
```
